# ronge-gongzhonghao

一套从「长报告」到「公众号可读长文」的完整流水线：**压字数 → 去 AI 味 → 做移动图 → 排 HTML → 过微信编辑器**。

核心就五句话：

1. **结果先行**：标题给结论，前三屏给完答案。
2. **短句**：一句一个意思，一段 1–3 句，不写连接词。
3. **一节一件事**：小标题是句子，不是名词。
4. **图是论据**：一图一结论，图上字要大，手机能看清。
5. **重点有底色**：数字和判断用淡金高亮，别只加粗。

## 何时用

- 把论文/研报/长文改成公众号文章；
- 用户说文章"太 AI""太啰嗦""没人爱看""排版土""图片糊"；
- 需要产出一份能直接粘贴到微信公众号编辑器的 HTML；
- 需要把关键数字/结论做成高亮、结论卡、金句卡。

## 输入

- 原文（Markdown/PDF/Word/旧公众号稿）；
- 数据与图（可选，没有就先做图）；
- 目标字数（默认 2500–3500 字，最多 5 节 + 结尾）。

## 输出

- `article.md`：公众号源稿（支持 `==高亮==`、`:::lead`、`:::note`）；
- `article.html`：自包含 HTML（图片 base64，内联样式，可直接复制）；
- `preview.png`：手机端长图预览（750px 宽）；
- 配图：750×H 的移动版图（仿宋、大字号、一图一结论）。

## 工作流

### 第 0 步：先判断"能不能删一半"

拿到长文先做减法，不做润色：

- 删方法论细节、公式、稳健性检验清单 → 压成 3–4 句；
- 删重复结论（开头、中间、结尾各说一遍的，只留两处）；
- 删自嘲、meta、过渡段、"本文/下面/接下来/值得注意"；
- 删与主线无关的事件叙述；
- 目标：原文 5000 字 → 2800 字左右；长图 11000px → 8000px 以内。

### 第 1 步：写大纲（结果先行）

固定骨架，按需增删：

```
标题（给结论，≤ 22 字）
副标题（方法/代价，一句话）
导语（3 行内给完答案）
01｜这轮发生了什么        ← 事实 + 一张真实K线/趋势图
02｜核心结论是什么        ← 分布/区间 + 一张图
03｜怎么算出来的          ← 四步，每步 2–3 句
04｜条件/情景             ← 三种世界或分情形
05｜催化/变量             ← 只看方向，或排序
06｜怎么验证              ← 3–5 条可检验指标
最后                       ← 一句话回扣 + 互动
```

标题不要卖关子。例：`A股这轮底，大概率在 3200–3420`。

### 第 2 步：写正文（去 AI 味，最重要）

**先读两篇**：
- `references/banned-words.md`：禁用词表（10 类，约 200 条，带替换建议）；
- `references/how-to-write.md`：写法手册（标题/开头/段落/句子/数字/结尾 + 20 组改前改后）。

**硬规则**：

- 不写"先说清楚/只做一件事/本文/下面/接下来/换句话说/综上/值得注意的是"；
- 不用"首先/其次/另一方面/与此同时/因此/然而/但是"；
- 一段 1–3 句，长句拆短；允许一句话成段；
- 数字单独成句或放句首：`5月13号。上证4242.57。`；
- 小标题用句子：`这轮跌的，不是"大盘"`，不用"市场分析"；
- 每节最后一句是可传播的判断，不是总结；
- 幽默只留 2–3 处，放在转折处，不堆梗。

**写完先跑扫描器**，分数压到 3/千字以下再往下走：

```bash
python kit/check_ai.py article.md
```

它会给出：AI 味分数、命中词及出现次数、行号、上下文、替换建议。三档权重：元话语/公式句 5，连接词/大词/翻译腔 2，万能副词 1。

### 第 3 步：做移动版图（750px）

**不要**直接放 1200px 的图——手机上缩到 677px，字全糊。

规范（见 `references/layout-system.md`）：

- 画布 **750px 宽**，正文图内字号 ≥ 11px，标题 28–32px；
- 中文用 **仿宋（STFangsong）**，大标题用 **宋体（Songti SC）**，数字用 **Georgia**；
- 一图一结论：标题就是结论，kicker 说明图属于哪节；
- 只留必要标注，标签直接贴线/点，不用图例；
- 颜色：纸底 `#FAF7EF`、松绿 `#23453A`、金 `#B58B3E`、铁锈红 `#A6472E`；
- 真实数据优先：K线用 OHLC（红涨绿跌），不要用收盘价折线冒充。

### 第 4 步：生成 HTML

用本技能自带构建器（见 `kit/build_wx.py`）：

```bash
python kit/build_wx.py --md article.md --out article.html --preview preview.png
```

- 支持 `==文字==` → 淡金高亮；
- `:::lead` 块 → 开头"本文结论"卡（淡金底、无彩色边框）；
- `:::note` → 免责声明小字；
- 图片自动转 base64，输出单文件 HTML；
- 给所有元素补 `text-align:left`，避免微信报 `start/end`。

### 第 5 步：自检

先跑扫描器：

```bash
python kit/check_ai.py article.md          # 看分数、命中词、行号
python kit/check_ai.py article.md --json   # 机器可读
```

目标：**分数 < 3/千字**。超过 8 就重写，不要只换词。

再人工过一遍 `references/review-checklist.md`，重点：

- 标题是不是结论？
- 前 3 屏有没有给完答案？
- 有没有"本文/先说/只做/下面/接下来"？
- 每节是不是只讲一件事？
- 图上的字在手机上能不能看清？
- 有没有左侧彩色边、绿色大色块？（不要）
- 重点数字有没有底色高亮？
- 文末有没有免责声明（如涉及投资/医疗/法律）？

### 第 6 步：粘贴进公众号

见 `references/wechat-pitfalls.md`。要点：

1. Chrome 打开 HTML → `⌘A` → `⌘C`；
2. 后台新建图文 → 正文粘贴；
3. 图片没上传成功就手动传 750px 图；
4. 结构检测弹 `text-align: start/end`：确认段落已显式 `left`，否则点"继续插入"；
5. 标题、摘要、封面在后台单独填。

## 排版系统（速查）

| 元素 | 规则 |
|---|---|
| 正文 | 仿宋 17px，行高 1.95，段距 22px |
| 标题 | 宋体 22px，深墨绿 `#1F2723` |
| 数字 | Georgia，tabular-nums |
| 高亮 | 淡金底 `#F5E4A8` + 加粗，不要荧光黄 |
| 结论卡 | 淡金底 `#FBF3DA`，顶部不加彩色边 |
| 引文/金句 | 淡金底，宋体 19px |
| 小标题 | 金色编号 + 宋体标题 + 1px 沙线 |
| 分隔 | 短金线或留白，不用花哨符号 |
| 图片 | 750px 宽，图注 12px 灰色 |
| 禁止 | 绿色大块头图、左侧彩色边、圆角卡片堆叠、渐变、emoji |

## 常见失败

- **微信吃样式**：改用 `mdnice` / `wechat-format` 导入 Markdown，再复制；
- **图片裂**：手动上传 `figs/` 里对应的 750px 图；
- **太长**：砍到 2000 字 / 5 张图，把方法段并成一段；
- **太 AI**：删掉所有 meta 句，从事实开始；把"不是A，是B"的对仗拆掉；
- **图太糊**：重画 750px 版，不要缩放 1200px 图。
